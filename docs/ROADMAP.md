# Roadmap and acceptance criteria

Status legend: ☐ not started · ◐ in progress · ☑ done and verified. Stubs are labelled; nothing mock is presented as working.

## Phase 1: Planning ☑
Docs in this folder + `prisma/schema.prisma`. *Accept:* docs reviewed; schema validates (`prisma validate`).

## M1 Foundation ☑ (scoped: see notes)
Scaffold, migrations, auth, roles, seed, content schema validation, tokens/base components. *Accept:* sign up/in works; seed loads the Contrast module; CI green.
**Done:** scaffold, migration, credentials auth (email + password, bcrypt), roles (always server-read), enrollment, content schemas + loader + idempotent publisher with immutability checks, seed, base components, e2e + unit tests.
**Not done / known gaps:** login throttling, password reset and email verification were added in M8; OAuth providers not added; the Contrast lessons are skeletons (M2 authors them); CI workflow is written but has not run on GitHub yet.

## M2 Learning engine ☑ (scoped: see notes)
Prerequisites, quiz scoring, lesson completion, dashboard + timeline, full Contrast module content. *Accept:* direct URL/API access to a locked lesson is refused; lesson cannot complete without a passing check; tests cover rules.
**Done:** `src/lib/progression` as the only authority (access, ordered block views, server-side check scoring, idempotent completion, derived timeline, evidence-based weak areas); learner view never includes answer keys or explanations before an attempt; content after a check stays closed until it is passed; lesson stepper, My learning timeline and dashboard (where am I / do next / improve); three Contrast lessons with all ten loop blocks, 15 quiz questions and nine purpose-built demos (reading order, button visibility, type readability, grouping, text over video, motion clarity, brand lockup, figure/ground, interactive WCAG contrast lab). Tests: 29 unit/integration (incl. concurrent submits, skip-ahead, locked access, key leakage) and 5 Playwright e2e (incl. axe scan).
**Not done / known gaps:**
- All Contrast content is `DRAFT`, shown to learners only with `CONTENT_PREVIEW=true`. It has not had editorial review. Real-world examples are described generically; licensed screenshots are still needed (see `reviewNotes` in each lesson).
- Task and reflection blocks are shown but not collected or assessed (M3). They do not gate completion.
- No module assessment yet, so a module's "complete" means lessons complete only.
- Knowledge checks are machine-scored choice questions only; a failed check can be retried immediately with the same questions and shows explanations for missed ones (no cool-down, no question rotation).
- No placement/diagnostic, rate limiting, or lesson notes/saved concepts. Level gating (Intermediate) is M4.
- Block "viewed" means the learner pressed Continue; it is not evidence of reading time or understanding.

## M3 Submissions + AI grading ◐ (built and tested with a stand-in evaluator; real model path NOT verified)
Private uploads, poster assignment, rubric, provider, validation, server-side scoring, feedback, resubmission, appeals. *Accept:* 95% total with failed mandatory criterion fails; malformed model output never yields a score; no-key mode reports `not_configured`.
**Done and tested:** published poster rubric v1 (two required criteria) and assignment; private storage and decode-based upload validation; assignment gate (lessons complete, attempts, amend-on-evidence, retry-without-attempt); scoring authority with mandatory minimums; model-output schema that ignores model-claimed totals; deterministic checks; atomic single evaluation under concurrency; one validated retry then `FAILED_TO_EVALUATE` with no score; `not_configured` path; hourly rate limit; `applyEvaluation` as sole writer of assessment progression; module completion requires the assessment; brief and results screens (every state, remediation links, axe clean); appeals and anonymised reviewer tool with uphold/override; owner-only files (404 for others, 401 anonymous). 105 unit/integration tests (several mutation-checked) and 11 Playwright tests.
**Partly verified (see `docs/GRADER_CALIBRATION.md`):** the `ClaudeProvider` has now been called for real once (accepted by the API, validated, scored by the server, about $0.12 and 60 s per poster, high-quality grounded feedback). Five more calibration samples failed because the account ran out of credit, so discrimination, prompt-injection resistance, variance and agreement with human reviewers are **still unmeasured**. Original note: the `ClaudeProvider` had never been called, with no `ANTHROPIC_API_KEY` in this environment. It type-checks against the SDK, but whether the API accepts the structured-output schema, how the model scores real posters, prompt-injection resistance, and cost per submission are all unmeasured. Every e2e "result" came from the test-only evaluator.
**Known gaps:**
- ~~Evaluation runs synchronously inside the submit action~~ Fixed in M6 (background queue).
- Local-disk storage is dev-only. Images only: PDFs, video and prototype links are not inspected.
- No server-side refusal fallback: a model refusal becomes `FAILED_TO_EVALUATE` with a review flag, but nothing lists such submissions for a person, and a learner cannot appeal without a completed evaluation. Low-confidence results are applied and flagged but only reach a reviewer if the learner appeals.
- Appeals: failed results only, one per evaluation, human decision is final, an override cannot revoke a pass, no SLA or notifications. Reviewer role is CLI-only.
- After the third failed attempt only an appeal can proceed (no remediation-reset flow; M4). No cool-down between retries.
- No grading-consistency or AI-vs-expert calibration tracking. The rubric anchors and assignment are unreviewed drafts.
- Per-user rate limit counts evaluation starts from the audit table; it is not a global cost cap.

## M4 Capstone + unlock ◐ (built and tested with the test-only evaluator; real model path still NOT verified)
Capstone gating, level unlock, remediation, skill profile from evidence. *Accept:* next level unlocks only via passing capstone + mandatory checks; concurrent submits are idempotent.
**Done and tested:** a three-piece "Contrast campaign" capstone and rubric (85% pass; contrast, accessible contrast and consistency are required criteria); level definitions with scope statement and required competencies, validated by the loader; capstone access needs every module and module assessment; one `assessLevel` derivation used by the gate and every screen; unlock only in `completeLevelIfEligible`, idempotent under concurrency (6 simultaneous attempts -> one record); required skill must be >= 80 on latest evidence, so a 91-96% capstone does not unlock past a weak required competency, and it unlocks automatically once the skill is demonstrated by retaking the check; level lock enforced in lesson and assignment gates; completion record as an evidence snapshot that names test evaluators and states what it does not show; remediation (one reset, new passing checks required, action plan, two extra attempts granted once); skill profile from evidence only; timeline with all four tiers (later tiers shown as "not written yet"); human override unlocks through the same gate. 138 unit/integration tests (five rules mutation-checked) and 14 Playwright tests (axe clean on the new pages; screenshots reviewed at desktop and 390 px).
**Bugs found while building:** the lesson page hid the knowledge-check form once a lesson was complete, which would have made remediation and "retake to demonstrate the skill" impossible; fixed. Two level-heading display flaws fixed after reviewing screenshots.
**Not verified:** the real `ClaudeProvider` has still never been called (no `ANTHROPIC_API_KEY`). Every capstone result in tests and in the browser came from the test-only evaluator, and the completion record says so.
**Known gaps:**
- One module and one capstone are authored; Intermediate/Advanced/Professional have no content. The record is labelled "Contrast foundations", not "Beginner".
- Thresholds and the reset policy (80, 85, one reset, two extra attempts) are product defaults with no data behind them.
- Remediation re-uses the existing knowledge checks (same questions, retakeable immediately, no cool-down), so it can be passed by repetition; it does not grade any new practice work.
- A learner can pass a lesson check, so "latest evidence" can be refreshed by retaking until it passes; no cool-down or question rotation.
- The record is a database snapshot only: no PDF, share link or verification URL (M5 covers sharing). No expiry or revocation.
- A completion cannot be revoked if later evidence falls below 80.
- No placement/diagnostic, so `enrollment.startTier` is always Beginner.
- A capstone that is passed but blocked by a required skill cannot be resubmitted; the only route is retaking the check. If that skill is only measurable through the capstone (not the check), this would trap the learner. It is true for the current content only because the lesson check covers the required skill.

## M5 Portfolio + peer review ◐ (built and tested with the test-only evaluator; real model path still NOT verified)
Visibility controls, shareable page, structured peer review. *Accept:* private by default; peer feedback has no effect on progression.
**Done and tested:** projects can be made only from the owner's assessed work and start Private; Private / link-only / Public with one access rule used by pages **and** image requests and re-checked every request (un-sharing and moderator holds revoke an already-open image URL at once); allow-list public read model (no email, account name, ids, storage keys, file names, change notes, appeals or raw output; a test plants and searches for each); display names separate from the account and refused if they look like contact details; random public handle only for Public; EXIF/GPS stripped from served images with orientation applied; evidence opt-in, labelled by assessor, "Verified" only for a passed claude/human result and never for the test evaluator; structured plain-text peer feedback (self-review, private/held and blocked all refused, one per person atomically, length caps, hourly limits); owner hide/restore/delete/block; reports and a moderator queue (hold forces Private and cannot be re-shared, hide review, dismiss, one moderator wins, no moderating own work, audited); peer and moderation code verified to touch no progression or assessment rows or imports; `noindex` meta, `robots.txt` and `X-Robots-Tag`. 197 unit/integration tests (11 privacy and safety rules mutation-checked) and 17 Playwright tests (axe clean on the edit, public, gallery and moderation pages; screenshots reviewed at desktop and 390 px).
**Not verified:** the real `ClaudeProvider` has still never been called (no `ANTHROPIC_API_KEY`), so every assessment shown on a portfolio in tests came from the test-only evaluator and is labelled so.
**Known gaps (important before any launch):**
- **No automated screening of uploaded images or text.** Public hosting of user content relies on manual moderation and reports. This is the biggest open risk.
- No takedown/legal process, content policy or terms, no account or data deletion, no email notifications, no rate limiting on anonymous reads.
- No custom handles, gallery search/filters, revision history or earlier attempts on a project, or completion records on portfolios.
- Work under appeal cannot be added until the appeal resolves.
- Local-disk image storage is dev-only; shared images are re-encoded on every request with no caching.
- Verified marks depend on the provider recorded at assessment time; there is no audit tool yet for re-checking old results.

## M6 Background grading + operator resilience ◐ (built and tested with the test-only evaluator; real model path still only partly verified)
Move the 60 s assessment off the request path, classify provider failures, and give operators and reviewers a way to act. *Accept:* submit returns at once; a billing/auth failure pauses without losing or scoring anything; crashes recover; refused work can be assessed by a person.
**Done and tested:** Postgres job queue (`SKIP LOCKED`, one active job per submission, backoff 1/5/20 min, lease and reclaim, stuck stop); error classification (billing, auth, rate limit, overloaded, timeout, bad request, refusal, invalid output) with pause-not-fail for billing/auth; separate worker (`npm run worker`) and secret-protected tick endpoint; health probe auto-resume; daily budget cap; learner status page that updates itself (queued with position, running, paused, retrying, needs a person); owner-only status API; `/admin/assessments` (queue, pause banner, spend, attention list; admin-only controls, reviewers read-only); human first assessment through the same scorer and progression; fault-injecting test evaluator. 264 unit/integration tests and 20 Playwright tests (worker running as a real second process, axe clean, screenshots reviewed at desktop and 390 px). Mutation-checked: SKIP LOCKED, one-active-job, lease reclaim, rate-limit attempt accounting, billing-pauses, human-assess guards.
**Not verified:** only the **billing** error mapping was ever seen on the live API (HTTP 400 `invalid_request_error`, "credit balance is too low"); the others follow the SDK's documented error classes and are tested with constructed errors. The real grader is still uncalibrated (discrimination, injection resistance, variance, human agreement) and capstone cost/latency are unmeasured.
**Known gaps:**
- No external alerting (email, Slack, pager): a pause is visible only on the admin screen.
- The queue lives in the primary database: fine at this scale, not for high volume. No worker autoscaling.
- Spend is an estimate from recorded tokens at configurable list prices, not an invoice; failed provider calls that return no token counts are not counted.
- Queue position ignores jobs held back by backoff, so it is rough; there is no time estimate.
- A worker that hangs beyond the 6-minute lease while still running could in theory finish after its job was reclaimed; the lease is longer than the provider's timeout, so this needs a stuck process rather than a slow call.
- Human first assessments are final (no appeal), carry no per-criterion strengths/improvement text beyond the reviewer's comment, and there is no second-reviewer check.

## M7 Pre-launch safety package ◐ (built and tested; policy text is draft and needs legal review)
Close the gaps listed under M5. *Accept:* nothing is Public until a person approves what is shown; there is a way to report and take work down; people can delete their data; anonymous reads are limited.
**Done and tested:** pre-moderation of Public with content-bound approval (edits send it back to review; reviewers cannot approve their own work; one decision wins; decisions on content the owner changed meanwhile are refused); weak text screening (contact details, links, short term list) on shared text and peer feedback; image-screener hook with a "not screened" verdict; in-app notices for approvals, rejections, holds, releases and hidden feedback (never naming a reporter); DB-backed rate limits on public pages, images and the report form; account deletion (password and typed confirmation, last-admin guard, files removed after commit, audit log de-identified, deleted sessions end); draft content policy, terms and privacy pages; public report form and takedown queue with 90-day contact retention. Mutation-checked: approval condition in the access rule, reset-on-edit, content fingerprint, gallery filter, deletion password/project/file/last-admin guards.
**Not done / known gaps:** see `SAFETY.md` ("Not built"). Most important: no automated image screening; link-only sharing is not pre-moderated; the legal pages are drafts; no email; no account suspension or takedown appeals; no data export.

## M8 Account security ◐ (built and tested; email delivery verified only through the dev outbox)
Close the M1 gaps ("no login rate limiting or password reset yet; no email verification"). *Accept:* guessing is throttled; reset and verification work end to end; sessions can be ended; unverified accounts cannot share.
**Done and tested:** password policy; per-account and per-client sign-in throttling; constant-cost unknown-email sign-in; verification and reset links (hashed, single-use, expiring, newest wins, scanner-safe); identical reset responses; session versioning with change-password and sign-out-everywhere; verified-email gate on sharing, feedback, reports and appeals; mailer interface with SMTP and dev outbox; security headers. 334 unit/integration tests and 30 Playwright tests (axe clean). Mutation-checked: token single-use, expiry, session end on reset, unknown-address silence, account throttle, common-password check.
**Not verified / gaps:** see `ACCOUNT_SECURITY.md`. Most important: the SMTP adapter has never run against a real server; no 2FA, no CSP, no breached-password check, and signup still reveals registered addresses.

## M9 Brand Design and UI Design curriculum ◐ (authored and tested with the test-only evaluator; DRAFT, unreviewed)
Add the other two MVP disciplines at the same depth as Graphic Design. *Accept:* each new path runs end to end on the existing engine rules; nothing path-specific leaks across paths.
**Done and tested:** `brand-design` and `ui-design` Beginner paths (see `CONTENT_AUTHORING.md`): 6 lessons with checks, 7 new original demos, 2 module assessments and 2 capstones with 4 rubrics; one path-generic curriculum test suite; engine proof per path (lesson order and enrolment, gated assessments, capstone, mandatory minimum, required-skill gate with retake, honest level record); Playwright per path (all demos render with captions, axe clean, screenshots reviewed at desktop and 390 px). 372 unit/integration tests and 33 Playwright tests.
**Bugs the second and third path exposed, fixed:** remediation and retake links offered lessons from *other* paths for a shared competency (now scoped to the learner's path, mutation-checked); "UI" titled "Ui"; unordered path list and ten e2e enrolments that assumed one path; a published rubric's competency mapping could drift from its file without being flagged (now immutable); a capstone could measure a required competency with two criteria (now rejected by the loader).
**Not done / gaps:** content is AI-drafted and unreviewed by a brand or UI practitioner, and is DRAFT only; one Beginner module per path, nothing above Beginner; rubrics and thresholds are uncalibrated against the real grader (needs API credit) and the grader cannot measure fonts, hex values or target sizes from pixels, so assessments rely on learner-reported measurements; demos are original illustrations, not licensed real-world examples; images only (no prototypes or links); competency evidence is global across paths by design, so a skill demonstrated in one path counts as the latest evidence in another.
